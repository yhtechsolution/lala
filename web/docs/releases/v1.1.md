# Version 1.1

Release date: 26 October 2026
Component: LALA Guesthouse Web Admin Portal

## Overview
Version 1.1 extends the Firebase-connected administrator portal with account recovery, explicit session choices, profile and password controls, and a worldwide guesthouse discovery map. Local acceptance was confirmed by the project owner before preparing these notes. The GitHub release commit and hosting deployment are recorded separately; these notes do not claim a deployment has occurred.

## Added
- Forgot-password requests using Firebase Authentication email delivery and the Firebase password-reset flow.
- Generic reset-request confirmation that does not disclose whether an email address has an account.
- Remember me at sign-in: persistent sign-in on the device when selected, or browser-tab session persistence when unchecked.
- My account page showing account email and verification status, administrator display-name editing, password changes requiring current-password reauthentication, and sign-out.
- Interactive worldwide discovery map using live guesthouse coordinates, listing markers, price/rating cards, city filtering and search by guesthouse, city or country.
- Listing selection focuses the corresponding marker and opens its information popup. Reset restores the world view.

## Fixed and improved
- Replaced the first map implementation's sandboxed embedded document with direct page rendering and an explicit tile referrer policy, addressing the map-loading problem observed during local review. The initial implementation of the discovery map was not shipped but worked on locally.
- Removed the Botswana-only country and coordinate-boundary filters. All countries qualify when latitude and longitude are valid finite numbers.
- Retained the map instance during search and selection rather than repeatedly rebuilding the entire embedded map.
- Added map loading timeout, tile-error feedback, retry controls, responsive resizing and cleanup when leaving the page.
- Popup content uses text nodes so listing text is not interpreted as executable HTML.

## Validation
- TypeScript check passed in the preparation environment.
- Production build passed in the preparation environment.
- 27 automated tests passed, including account recovery, password reauthentication, session choices, profile field restrictions, coordinate validation, popup safety and map component lifecycle/error handling.
- The project owner confirmed that the admin portal worked correctly during local review after applying the global-map fix.
- Automated Firebase and map tests use mocks. Specific real-email delivery, session behaviour across browser settings and deployed permissions should be recorded in the team's acceptance evidence rather than inferred from these tests.

## Compatibility and operating notes
- No new npm packages, Firestore schema changes or security-rule deployment are required by this iteration.
- Existing Firebase authentication, administrator membership checks, guesthouse management, dashboard, analytics, communications directory and branding are retained.
- The map is part of the web administrator portal. Mobile application code is not changed by this iteration.
- Map rendering requires internet access to the Leaflet 1.9.4 assets on unpkg.com and OpenStreetMap background tiles. OpenStreetMap attribution is retained and its tile usage policy applies: https://operations.osmfoundation.org/policies/tiles/.
- Listing coordinates must be numbers: latitude -90 to 90, longitude -180 to 180. Missing or invalid coordinates are excluded and counted; no coordinates are invented or written back. Zero coordinates are mathematically valid and should be checked if unexpected.
- Prices continue to use BWP because the shared listing schema does not provide per-listing currencies.
- Display-name editing updates the existing Firestore administrator profile used by the portal. It does not change the login email, administrator permissions or Firebase Auth display name.
- Remember me and logout apply to this application's device/browser session, not to all devices. Explicit logout remains appropriate on shared computers; browser session-restore behaviour can vary.

## Outside this release
Public administrator registration, account provisioning/deletion, mandatory email verification, email-address changes, global session revocation, inactivity timeout, mobile map integration, booking availability and additional currencies.

## Release procedure
Commit the locally reviewed application files and these notes to simba-branch, inspect the staged changes, and push normally. Do not force push. Pull-request review, merging and hosting deployment remain separate steps controlled by the project owner. Record the resulting commit SHA and deployment details in the team's release record after those actions complete.
